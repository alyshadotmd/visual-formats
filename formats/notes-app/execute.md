# Notes App Format — Implementation SOP

## Reference examples (look here first)

To find examples, look in the shared `../../files/` folder for any file whose name contains `vf=notes-app`.

## What this format is

A screenshot styled as a real Apple Notes card, chrome and all (back arrow, undo/redo, share, ellipsis), carrying whatever text the ad needs: a single tip, a confession, a quote, a reminder, or one point of a longer list (pair with the `Listicle` format when it's the latter). This is a device, not a structure — it answers what the text is sitting inside, not how many points there are.

It works because a native iOS note reads as something a real person jotted down, not a designed brand asset, which lowers the "this is an ad" guard the same way handwriting does for Post-it, but with a typed, tidy, ownable-by-anyone register instead of a handwritten one.

Strongest for **single tips, confessions, quotes, reminders, and as one card in a longer listicle sequence.**

The one property to protect: **the chrome has to read as a real Apple Notes card**. An overly designed or branded mockup breaks the disguise.

## Inputs

Expect a **messaging angle** carrying the tip, confession, quote, or reminder, and (when this card is one point of a longer sequence) the other points in that sequence. The angle carries the message; this SOP governs how it sits inside the Notes-card device.

## Anatomy

1. **The Notes card:** real or real-looking Apple Notes chrome, cropped tight so the chrome reads clearly and only the relevant text shows.
2. **The text:** typed register — short, personal, plain. Reads like the person actually wrote it in their own notes, not brand copy pasted in.
3. **The base image (optional):** the Notes card can float over a photo (lifestyle, product, plain background) or stand alone against a flat color.

## Build rules (priority order)

1. **The chrome has to be legible and real-looking.** If it doesn't clearly read as Apple Notes, the disguise doesn't work.
2. **Crop tight to one idea.** Keep the note to exactly one thing to read, not a scrollable wall of text.
3. **Write in a typed-personal register**, not marketing copy. Short, plain, a little unpolished.
4. **Keep every card in a sequence visually consistent** (same crop style, same chrome position) when this card is one point of a list, so the sequence reads as one system.
5. **Specific, real claims; no absolutes or banned phrases.** Banned: overly designed/branded Notes-card mockups that don't look like a real note, walls of text, marketing phrasing inside the note.

## Length caps

| Element | Cap |
|---|---|
| Text per card | ≤2 short lines, one idea |

## Build steps

1. Read the brief: the angle and the point/tip/note it needs to carry.
2. Write the point/tip/note in plain, personal language.
3. Type it into (or mock up) an Apple Notes card; crop tight, keep the chrome visible.
4. Decide on a base image or flat background if one is needed.
5. If this is one point of a longer sequence, check whether the ad also qualifies as `Listicle` and plan the full sequence together, keeping every card visually consistent.
6. Claims pass (validate any claim in the note).
7. Legibility check at thumb size.
8. Deliver: note text, crop/chrome direction, base image direction if used, sequence notes if applicable.

## QA checklist
- [ ] Notes chrome is visible and reads as real
- [ ] Cropped to one idea, no wall of text
- [ ] Text reads personal/typed, not like marketing copy
- [ ] If part of a sequence, visually consistent across cards
- [ ] Claims validated; no absolutes/banned phrases
