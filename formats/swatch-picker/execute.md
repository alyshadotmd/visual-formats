# Swatch Picker Format — Implementation SOP

## Reference examples (look here first)

To find examples, look in the shared `../../files/` folder for any file whose name contains `vf=swatch-picker`.

**Study the example first** — notice how quickly the cuts land between colors and how the selector stays legible as a real page element.

## What this format is

A cursor clicks through color or variant swatches like on a product page, and the product photo swaps to each color. It works because it mimics the familiar, trusted motion of browsing a real product page, and watching the range of options cycle makes the viewer curious about which one they'd pick.

Strongest for **showing color or variant range on a product with several options**, where the range itself is the selling point.

The one property to protect: **the selector has to look clickable and real**, like an actual product-page element. If it doesn't read as something you could click, the illusion of browsing breaks.

## Inputs

Expect a **messaging angle** (the hook or offer to hold above the selector) and the **product photography in each color/variant** the swatches will cycle through. The angle sets the hook; this SOP governs the selector mechanics and pacing.

## Anatomy

1. **The hook/offer line:** sits above the selector and stays on screen the whole time.
2. **The swatch selector:** a product-page-style swatch row that looks clickable.
3. **The product photo:** swaps to match whichever swatch is "clicked."
4. **The cursor/tap:** the device that drives the clicks through the swatches.

## Build rules (priority order)

1. **Recreate a simple product page selector;** the swatches must look clickable.
2. **Cut quickly between colors, one per click,** so it feels like browsing.
3. **Put the offer or hook above the selector** so it stays on screen the whole time.
4. **Keep it to one message, one offer or CTA.**
5. **Specific, real claims; no absolutes or banned phrases.**

## Length caps

| Element | Cap |
|---|---|
| Message/offer | 1 |
| CTA | 1 |

Match the number of colors cycled to the real product's variant range, confirmed when briefing.

## Build steps

1. Read the brief: angle/hook, the product's color or variant range.
2. Recreate a clickable-looking product-page swatch selector.
3. Place the hook/offer line above the selector.
4. Cut quickly between colors, one swap per click, cycling the product photo to match.
5. Confirm one message and one CTA carry the whole ad.
6. Claims pass (validate any claim in the hook or offer).
7. Legibility check at thumb size.
8. Deliver: hook/offer copy, selector direction, color/variant sequence, claims flags.

## QA checklist
- [ ] The device carries the message
- [ ] It reads at a glance on a phone
- [ ] Honest claims; no absolutes or banned phrases
