# Point to Screen Format — Implementation SOP

## Reference examples (look here first)

To find examples, look in the shared `../../files/` folder for any file whose name contains `vf=point-to-screen`.

## What this format is

A phone films a real screen (laptop, monitor, tablet, another phone) while a hand points at or clicks through what's on it, usually with someone talking you through it. It works because the filmed device — glare, edges, and all — reads as real rather than a produced screen recording, and because the hand steers the viewer's eye beat by beat, so the pitch still lands even on mute.

Strongest for **shopping walkthroughs, product or site demos, and any proof-driven claim that's stronger shown live on a real page than described** (an offer, a result, a cart building in real time).

The one property to protect: **it has to be a real screen filmed by a camera** — the device, the glare, the edges all visible. Swap in a clean screen recording or a screenshot and the format's believability is gone.

## Inputs

Expect a **messaging angle** — the voiceover and hook — plus the specific screen content the ad will film: the brand's website, an app, a cart, reviews, or a doc. The brief should also set the one path the hand will walk start to finish. The angle carries what's said; this SOP governs how it's filmed.

## Anatomy

1. **The device:** a real screen (laptop, monitor, tablet, or phone), filmed handheld and over the shoulder.
2. **The hand:** points at, taps, or clicks through what's on the screen, steering the eye beat by beat.
3. **The screen content:** carries the proof or the pitch — the website, app, cart, reviews, or doc.
4. **The voiceover:** narrates while the hand matches each line with a point or click.
5. **Captions:** carry the voiceover for sound-off viewing.

### Beats (in order)
1. Open on the screen already showing the thing worth seeing (the deal, the result, the product page); say the hook out loud in the first line.
2. Walk one path start to finish (for a shopping walkthrough: offer, pick products, cart showing the price), with the hand pointing or clicking on every beat.
3. Close by repeating the hook and the urgency (e.g. "while the deal is still live").

## Build rules (priority order)
1. **Film a real screen on a phone, handheld and over the shoulder.** A little glare and device edge is what makes it feel real; don't swap in a clean screen recording.
2. **Open on the screen already showing the thing worth seeing** (the deal, the result, the product page), with the hook said out loud in the first line.
3. **Match every voiceover line to a point or click.** The hand is the edit: it tells the viewer where to look.
4. **Walk one path start to finish** rather than jumping between unrelated screens.
5. **Keep key numbers (price, discount) readable on a phone.**
6. **Add captions** so it works on mute.
7. **Honest, specific claims.** No absolutes or banned phrases.

## Length caps

| Element | Cap |
|---|---|
| Screen filmed | 1 real device, handheld |
| Path walked | 1, start to finish |
| Pointing/clicking | on every narrated beat |
| Hook | repeated at open and close |

## Build steps

1. Read the brief: the voiceover and hook, and which screen (site, app, cart, doc) carries the proof.
2. Set up the real device and camera (phone filming a laptop, monitor, tablet, or phone), handheld, over the shoulder.
3. Open on the screen already showing the thing worth seeing; say the hook in the first line.
4. Walk one path start to finish, matching the hand's point or click to each voiceover line.
5. Keep key numbers (price, discount) readable on a phone.
6. Add captions for sound-off viewing.
7. Close by repeating the hook and the urgency.
8. Claims pass (claims specific, honest, validated; no absolutes/banned phrases).
9. Deliver: screen/path chosen, voiceover script with matching point/click beats, captions, claims flags.

## QA checklist
- [ ] Real device on camera, not a screen recording
- [ ] Hand points or clicks on every beat
- [ ] Key numbers (price, discount) are readable on a phone
- [ ] Captions on
- [ ] Honest claims; no absolutes or banned phrases
