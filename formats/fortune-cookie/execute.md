# Fortune Cookie Format — Implementation SOP

## Reference examples (look here first)

To find examples, look in the shared `../../files/` folder for any file whose name contains `vf=fortune-cookie`.

## What this format is

The message printed on a fortune cookie slip, held in hand. It works because a fortune reads as a prediction or a nudge rather than an ad, so a line printed on the slip feels discovered rather than sold, and the tiny, personal format invites a close read.

Strongest for **playful, offer-led hooks** where a short, fortune-style line ("You will save 30% today") lands better than straight ad copy.

The one property to protect: **the device carries the message** — the slip has to be legible and read as a real fortune, not a caption pasted onto a cookie photo.

## Inputs

Expect a **messaging angle** (the line to print, written like a fortune: a prediction, a nudge, or the offer). The angle supplies the line; this SOP governs how the slip is shot and styled.

## Anatomy

1. **The slip:** a real (or realistic) fortune cookie slip, the hero of the frame.
2. **The hand:** usually holds the slip, often beside a cracked cookie.
3. **The printed line:** the ad's message or offer, written like a fortune.
4. **The simple background:** kept plain so the tiny slip stays readable.

## Build rules (priority order)

1. **Shoot a real slip in a real hand;** a cracked cookie in frame helps it read instantly.
2. **One short line on the slip,** written like a fortune: a prediction, a nudge, or the offer.
3. **Keep the background simple** so the tiny slip stays readable on a phone.
4. **One message, one offer or CTA.**
5. **Specific, real claims. No absolutes or banned phrases.**

## Length caps

| Element | Cap |
|---|---|
| Printed line | ≤12 words |
| Offer/CTA | 1 |

## Build steps

1. Read the brief: the offer or nudge the line should deliver.
2. Write the line in fortune-cookie voice: a prediction, a nudge, or the offer.
3. Shoot the slip in a real hand, with a cracked cookie in frame if possible.
4. Keep the background plain so the slip stays the focal point.
5. Claims pass (offer terms accurate; no absolutes or banned phrases).
6. Legibility check at thumb size.
7. Deliver: printed line, shot direction, claims flags.

## QA checklist

- [ ] The device carries the message
- [ ] It reads at a glance on a phone
- [ ] The slip and hand look real, not staged flat
- [ ] Honest claims; no absolutes or banned phrases
